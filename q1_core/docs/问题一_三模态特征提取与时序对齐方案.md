# 问题1：文本、语音、视觉三模态特征提取与时序对齐实施方案

## 1. 目标

问题1的目标不是直接完成情感分类，而是从附件1的原始视频中构建可复现、可核验的三模态时序特征，并让其输出接口与问题2/3的输入规范兼容。

整体流程：

```text
原始视频
   ↓
问题1：模型A / 特征生成管线
   ↓
Text / Audio / Vision 三模态时序特征
   ↓
统一时间组织、Mask、Padding、时间映射
   ↓
问题2/3：模型B
   ↓
情感极性分类 + 情感强度回归
```

推荐优先采用 `aligned_50` 思路，也就是将三模态组织为最多 50 个彼此对应的时间位置。

---

# 2. 推荐总方案

当前建议组合：

| 模态 | 主方案 | 原始输出 | 推荐原因 |
|---|---|---:|---|
| 文本 | BERT-base-uncased + MFA | token/word × 768 | 与附件2的 768 维文本最接近 |
| 语音 | COVAREP | frame × 74 | 与经典 CMU-MOSEI 的 74 维声学特征体系最接近 |
| 视觉 | OpenFace 2.2 | frame × d_v | AU / pose / gaze 与情感语义清晰，且可复现 |
| 时间对齐 | MFA + word-level pooling | 最多 50 个 word positions | 与 CMU-MOSEI 常见 word-level alignment 思路一致 |

最终建议输出：

```text
Text   : [50, 768]
Audio  : [50, 74]
Vision : [50, d_v]

Text Mask   : [50]
Audio Mask  : [50]
Vision Mask : [50]

timestamps  : [50, 2]
sample_id
valid_length
duration
label
annotation
```

如果问题2/3后续希望统一潜在空间，则再加 Adapter：

```text
Text   768 → 128
Audio   74 → 128
Vision d_v → 128
```

统一得到：

```text
H_text   : [50, 128]
H_audio  : [50, 128]
H_vision : [50, 128]
```

注意：

> Adapter 只能解决维度不一致，不能保证不同来源特征已经具有相同语义或统计分布。

# 3. 文本模态方案

## 3.1 输入

附件1的 `label-100.xlsx` 已经提供官方英文 transcript。

不建议重新使用 Whisper 生成新文本，因为：

1. 官方文本已经存在；
2. 重新 ASR 可能改变单词；
3. 会造成与标签文件不一致；
4. 不利于可复现。

因此文本支路使用：

```text
label-100.xlsx 中的 text
```

---

## 3.2 特征模型

推荐：

```text
bert-base-uncased
```

BERT-base hidden size：

```text
768
```

对于一句话：

```text
"I really love this movie"
```

不是简单取整句 `[CLS]` 后复制，而应该保留 token/word 级特征：

```text
I       → 768维
really  → 768维
love    → 768维
this    → 768维
movie   → 768维
```

得到：

```text
X_text_raw ∈ R^(L × 768)
```

其中：

```text
L = 当前样本有效词/token 数
```

---

## 3.3 WordPiece 合并规则

BERT tokenizer 可能将一个单词拆成多个 subword，例如：

```text
unbelievable
→
un
##bel
##ievable
```

推荐对属于同一原始单词的多个 subword hidden states 做 mean pooling：

```text
word_embedding
=
mean(subword_embeddings)
```

得到真正的 word-level：

```text
word_i → 768维
```

---

# 4. 文本时间戳：MFA 强制对齐

BERT 只给语义特征，不给单词在视频中的精确时间。

因此需要：

```text
audio.wav + 官方 transcript
        ↓
Montreal Forced Aligner
        ↓
每个 word 的 start_time / end_time
```

例如：

```text
I       0.32 – 0.48
really  0.49 – 0.91
love    0.92 – 1.20
this    1.21 – 1.39
movie   1.40 – 1.85
```

推荐优先使用：

```text
Montreal Forced Aligner（MFA）
```

备选：

```text
WhisperX
```

但由于本题已有官方 transcript，MFA 更自然。

# 5. 语音模态方案

## 5.1 主方案：COVAREP

推荐优先尝试：

```text
COVAREP
```

原因：

- CMU-MOSEI 经典设置中常见 74 维声学特征；
- 与附件2的 `Audio = 50 × 74` 在特征体系上更接近；
- 包含音高、声门、MFCC、声学韵律等与情绪相关的信息。

原始输出：

```text
A_raw ∈ R^(T_audio × 74)
```

每个声学帧包含：

```text
timestamp
74维 acoustic feature
```

---

## 5.2 Word-level Pooling

假设：

```text
love → [0.92s, 1.20s]
```

在这段时间内存在若干音频帧：

```text
a31
a32
...
a40
```

则：

```text
Audio("love")
=
mean(a31, a32, ..., a40)
```

最终每个文本 word 对应一个 74 维音频向量。

从而：

```text
X_audio ∈ R^(L × 74)
```

经过 Padding / Truncation：

```text
X_audio ∈ R^(50 × 74)
```

---

## 5.3 语音备选方案

如果 COVAREP 环境过于麻烦，可使用：

### 方案A：openSMILE

推荐使用 frame-level / LLD，而不是整段 Functionals。

流程：

```text
audio.wav
  ↓
openSMILE LLD
  ↓
frame × d_audio
  ↓
word-level pooling
  ↓
L × d_audio
```

然后通过 Adapter：

```text
d_audio → 128
```

### 方案B：WavLM / wav2vec2

例如：

```text
WavLM-base-plus
wav2vec2-base
```

通常 hidden size 为 768。

流程：

```text
audio waveform
    ↓
WavLM / wav2vec2
    ↓
T_audio × 768
    ↓
word-level pooling
    ↓
L × 768
    ↓
Audio Adapter
    ↓
L × 128
```

但注意：

> WavLM / wav2vec2 与附件2的 74 维声学特征并不是同一特征空间。

# 6. 视觉模态方案

## 6.1 主方案：OpenFace 2.2

推荐：

```text
OpenFace 2.2
```

可提取：

```text
Facial Action Units
Head Pose
Eye Gaze
Facial Landmarks
Face Detection Confidence
```

其中最关键的是：

```text
Action Units（AU）
```

例如：

```text
AU01 Inner Brow Raiser
AU02 Outer Brow Raiser
AU04 Brow Lowerer
AU06 Cheek Raiser
AU12 Lip Corner Puller
AU15 Lip Corner Depressor
AU25 Lips Part
...
```

这些视觉特征与情绪的关系更直接，也比 ViT 的黑盒 embedding 更容易写入数学建模论文和解释结果。

---

## 6.2 OpenFace 输出过滤

建议至少保留：

```text
timestamp
confidence
success

AU*_r    # AU intensity
AU*_c    # AU presence，可选

pose_Rx
pose_Ry
pose_Rz

gaze_angle_x
gaze_angle_y
```

不建议一开始把：

```text
全部 landmark 坐标
全部 HOG
全部 3D 点
```

全部塞进去，因为维度太大且解释复杂。

推荐先构建一个较紧凑的：

```text
visual_feature ∈ R^(d_v)
```

例如：

```text
AU intensity + head pose + gaze
```

---

## 6.3 Word-level Visual Pooling

假设：

```text
love → [0.92s, 1.20s]
```

在该时间范围内，OpenFace 对应帧为：

```text
frame 28
frame 29
...
frame 36
```

则：

```text
Vision("love")
=
mean(
    visual(frame28),
    ...,
    visual(frame36)
)
```

最终：

```text
X_vision ∈ R^(L × d_v)
```

之后：

```text
Padding / Truncation
→
X_vision ∈ R^(50 × d_v)
```

# 8. 为什么不建议视觉主方案直接使用 ViT / CLIP

ViT / CLIP 的优点：

```text
深层语义能力强
使用方便
通常 768 维左右
```

但它们可能同时编码：

```text
人物身份
衣服
背景
光照
物体
场景
```

而不仅仅是：

```text
面部情绪
```

对于本题：

```text
OpenFace / Py-Feat
```

在情绪语义与可解释性上更自然。

如果后续希望做增强实验，可以添加：

```text
OpenFace + ViT
```

作为视觉融合特征。

# 9. 三模态对齐：推荐 Word-level Alignment

不建议直接将整个视频机械地等分成 50 段。

更推荐：

```text
官方 transcript
      ↓
MFA
      ↓
每个 word 的时间范围
      ↓
┌───────────────┬─────────────────┐
↓               ↓                 ↓
BERT(word)   Audio pooling   Visual pooling
↓               ↓                 ↓
768维           74维              d_v维
```

对于第 i 个 word：

```text
Text[i]
Audio[i]
Vision[i]
```

都对应同一时间区间：

```text
[start_i, end_i]
```

因此：

```text
Text[i] ↔ Audio[i] ↔ Vision[i]
```

具有统一时间语义。

---

# 10. 最大长度统一为 50

假设样本实际 word 数：

```text
L
```

### 情况1：L < 50

使用：

```text
zero padding
```

并设置：

```text
mask[:L] = 1
mask[L:] = 0
```

### 情况2：L = 50

直接使用。

### 情况3：L > 50

优先方案：

```text
截断到前 50 个有效 word
```

但需要在日志和论文中记录该规则。

如希望更合理，也可以：

```text
保留情绪权重更高的连续 50 words
```

但第一版工程实现不建议增加复杂性。

---

# 11. 缺失值规则

## 文本

无 word：

```text
feature = 0
mask = 0
```

## 语音

某个 word 时间范围内没有有效音频帧：

```text
feature = 0
audio_mask = 0
```

## 视觉

如果 OpenFace：

```text
success = 0
或 confidence < threshold
```

则该帧无效。

若整个 word 时间范围内没有有效人脸帧：

```text
feature = 0
vision_mask = 0
```

```text

保存 features_aligned_50.pkl

Step 12

自动做完整性检查
```

# 15. 必须做的完整性检查

程序至少检查：

```text
样本数 == 100
sample_id 唯一
视频全部存在
音频全部抽取成功
MFA 是否成功
BERT 输出是否存在 NaN/Inf
Audio 是否存在 NaN/Inf
Vision 是否存在 NaN/Inf
所有输出第一维 == 50
Mask shape == [50]
timestamps shape == [50,2]
valid_length <= 50
label 与 sample_id 是否对应
```

对于失败样本：

```text
不要直接删除
```

应该写入：

```text
processing_log.txt
```

并尽可能通过：

```text
mask / zero padding
```

保留。

# 16. 实施建议

第一版优先把以下路径跑通：

```text
1个视频
   ↓
WAV
   ↓
MFA word timestamps
   ↓
BERT
   ↓
OpenFace
   ↓
Audio extractor
   ↓
word-level pooling
   ↓
统一为 50 步
   ↓
保存单样本
```

不要第一步就直接批量跑100条。

推荐调试顺序：

```text
1条 → 3条 → 10条 → 100条
```

先确保：

```text
时间戳正确
shape正确
mask正确
无NaN
无Inf
输出可以稳定读取
```

再批处理。

# 17. 当前推荐结论

问题1当前推荐主路线：

```text
文本：
BERT-base-uncased

文本时间对齐：
Montreal Forced Aligner

语音：
COVAREP 74维
（环境困难时 openSMILE fallback）

视觉：
OpenFace 2.2
（环境困难时 Py-Feat fallback）

时序组织：
word-level alignment

最大长度：
50

Padding：
zero padding

Mask：
Text / Audio / Vision 分别保留

最终接口：
Text   [50,768]
Audio  [50,74] 或 [50,d_a]
Vision [50,d_v]

后续模型B内部：
各模态 Adapter → 50×128
```

这套方案兼顾了：

```text
与 CMU-MOSEI 常见特征体系的接近程度
工程可实现性
论文可解释性
问题1与问题2/3的接口兼容性
问题3后续可解释性
```
